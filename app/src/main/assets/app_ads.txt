# 应用专属广告域名清单（唯一来源，随应用打包，运行时只读 —— 工程规则第 44 节）
#
# 格式：每行「<包名> <域名>」，UTF-8 / LF，忽略空行与 # 注释，通配符只允许 *. 前缀。
# 这些域名只对左侧包名对应的应用生效；其它应用请求同一个域名完全不受影响。
#
# 收录标准只有一条：域名本身必须是可确认的广告或追踪域名。命名里带 ads / tracker 不构成
# 证据（工程规则第 17、32 节）；域名一旦拦错，破坏的是应用功能本身，因此不做「看着像就收」。
#
# 条目按证据强度标注，标注写在所属小节里：
#   已确认 —— 域名来自广告平台的公开文档或广泛使用的去广告规则集，且该应用确属对应生态。
#   待确认 —— 域名已确认是广告 SDK 域名，但「该应用是否接入」尚未逐项验证。
#             收这类条目是因为它没有副作用：作用域只限左侧应用，该应用没用这个 SDK 时
#             整条规则不命中，等同于不存在；一旦命中就是真实拦截。是否真的生效，可以在
#             「网络活动」页与拦截通知里直接看到，不必猜。
#
# 与 assets/domains.txt 的关系：domains.txt 是全局清单，对所有应用生效；本文件是按应用
# 收窄的补充。二者都是只读内置规则，用户显式放行规则的优先级最高，可覆盖这里的任意一条。
#
# 本文件没有版本号，也不需要：它不导入持久层、没有用户覆写，每次启动整体重新加载，
# 因此不存在第 39.3 节那种「已安装用户拿不到新增条目」的问题。补充域名直接追加即可。
#
# 微信小程序：小程序运行在微信进程内，因此针对 com.tencent.mm 的规则自动作用于小程序。
# 但小程序与公众号的广告大量走微信自有接口（mp.weixin.qq.com 等），那些主机同时承载正文
# 与登录等核心功能，在域名层面拦截会直接破坏微信，故这里只覆盖小程序使用的第三方广告 SDK。
